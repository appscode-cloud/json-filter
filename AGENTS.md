# AGENTS.md

This file provides guidance to coding agents (e.g. Claude Code, claude.ai/code) when working with code in this repository.

## Repository purpose

`@appscode/json-filter` is a tiny single-file JavaScript utility published to npm. It projects/reshapes a JSON object by applying an ordered list of operations expressed via JSON-Pointer-style `$ref` paths. It is consumed by AppsCode / ByteBuilders front-end packages to declaratively pick and rename fields out of API responses without bespoke mapping code.

The package exposes a single default-exported function:

```js
import JsonFilter from "@appscode/json-filter";
const result = JsonFilter(jsonObject, operations);
```

Internally `operations` is folded over the input with `reduce`, each step producing the input for the next. Two operation shapes are supported: pure **Fetch** (`{ $ref: "#/path" }`) and **Fetch & Map** (an object whose values are `{ $ref }` descriptors), with optional dynamic key names when a key itself starts with `#` (interpreted as a relative pointer into the current element). When the running value is an array, each operation is applied per-element.

## Library API

### Default export

```js
JsonFilter(jsonOb: unknown, operations: Operation[]): unknown
```

`operations` is reduced over `jsonOb`. Each `Operation` is one of:

1. **Fetch** — `{ $ref: "#/json/pointer" }`
   - Returns the value at the pointer. `"#/"` returns the current object itself.
   - If the current value is an array, the fetch is mapped over every element.

2. **Fetch & Map** — an object whose entries each have a `{ $ref }` descriptor:
   ```js
   { newKeyName: { $ref: "#/source/path" }, other: { $ref: "#/" } }
   ```
   - For each key, the value is resolved by following its `$ref` from the current element.
   - If the **key** itself begins with `#`, it is treated as a relative JSON Pointer into the current element and the resolved value becomes the property name (dynamic keys).
   - Applied per-element when the current value is an array.

### Internals (`json-filter.js`)

- `arrayOrObject(ob, arrayFunc, obFunc)` — dispatch helper: `ob.map(arrayFunc)` when `Array.isArray(ob)`, otherwise `obFunc()`.
- `performOp(ob, op)` — applies a single operation; short-circuits when `ob` is falsy.
- The top-level default export is `(jsonOb, op) => op.reduce((ac, cr) => performOp(ac, cr), jsonOb)`.

All pointer resolution goes through `ptr.JsonPointer.get` from `json-ptr`.

## Build & bundling

`rollup.config.js`:

- `input`: `json-filter.js`
- `output`: `dist/json-filter.min.js`, `format: 'umd'`, global `name: 'JsonFilter'`
- Plugin order: `babel({ babelHelpers: 'bundled' })` → `commonjs()` → `nodeResolve()` → `terser()`

Because the entry imports `json-ptr` as an ES module, `nodeResolve` and `commonjs` are required to inline the dependency into the UMD bundle. Terser produces the minified, single-file artifact that ships to npm.

There is **no separate Babel config** — Babel uses defaults via `@rollup/plugin-babel`. If you need targeted browser support, add a `.babelrc`/`babel.config.json` and reference it.

## Tests

`test.js`:

- Plain Node script (no test framework, no assertions library) that `require`s the built `./dist/json-filter.min.js`.
- Defines a fixture `testOb` (a multi-step-form descriptor) and three example operation lists (`operations1`, `operations2`, `operations`).
- Logs the result of `JsonFilter(testOb, operations)` to stdout for visual inspection.
- `npm test` runs `rollup --config rollup.config.js && node test.js`, so it doubles as a build smoke test.

When adding behavior, extend `test.js` with new fixtures + `console.log` blocks (or migrate to a real test runner — none is currently required by CI).

## Release flow

1. Bump version locally if desired (CI will also overwrite it from the tag — see step 4).
2. Push a git tag matching `*.*` (e.g. `0.0.6`) to `master`.
3. `.github/workflows/release.yml` triggers on tags:
   - Checks out with `fetch-depth: 0`.
   - Installs deps with `npm ci`.
   - Builds via `npm run build`.
   - Writes `~/.npmrc` with `NPM_AUTH_TOKEN` from secrets.
   - Runs `npm --no-git-tag-version --allow-same-version version ${TAG}` to set the package version from the tag name.
   - Runs `npm publish --access public`.
4. Kodiak merges PRs automatically (squash) once approved/CI-green.

The legacy `appscode-json-filter-0.0.2.tgz` tarball is kept in-tree for consumers that pin to a direct-tarball install. Do not delete it without coordinating with downstream repos.

## Conventions & best practices

- **Single-file library** — keep `json-filter.js` small and dependency-light. Anything that needs more than JSON-Pointer resolution belongs in the consuming app, not here.
- **Default export only** — the package's public API is the default-exported function. Adding named exports is a breaking change for the UMD `JsonFilter` global.
- **`json-ptr` is the only runtime dep** — adding runtime dependencies bloats the UMD bundle for every consumer. Treat new `dependencies` (vs. `devDependencies`) as a deliberate, reviewed choice.
- **Bump `package.json#version` on every API change** — even though the release workflow rewrites it from the git tag, keeping the source-of-truth version in sync avoids confusion. Use SemVer (`0.x.y` while pre-1.0; breaking → bump `x`).
- **Match the `#/`, `#/path`, and dynamic-key (`"#/..."` as object key) semantics already documented in README.md** — these are the public contract. New shapes should be additive.
- **CI uses pinned action SHAs** — preserve the pinning when bumping versions; Dependabot is configured but `open-pull-requests-limit: 0` so updates are manual/Renovate-driven.
- **Do not commit `dist/`** — it is gitignored and produced by `npm run build` / `npm test` / the release workflow.
- **Do not commit `.idea/` or `node_modules/`** — both are gitignored.
- **`.npmignore`** keeps `.github/` out of the published tarball; if you add files that should not ship to consumers (fixtures, larger tests, docs assets), add them there too.
- **License** — Apache-2.0 (per `package.json`). If you add a `LICENSE` file, use the Apache-2.0 text and reference it from `package.json#license` (`"SEE LICENSE IN LICENSE"`) only if the metadata-string approach is no longer accurate.
